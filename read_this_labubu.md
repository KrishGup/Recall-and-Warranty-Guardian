# read_this_labubu.md

**Where things are (three lines):**

1. Guardian runs end to end on gren + Strands: `guardian seed` → `guardian serve` → click the logo (or `guardian sweep`) pulls live CPSC/NHTSA/openFDA recalls, matches them in code, adjudicates the ambiguous pairs with Opus, verifies the plan, pauses on the household gate, and after "Request full refund" in the dashboard drafts and "sends" the remedy (to `var/household/outbox` until SES/SNS are configured), then schedules the follow-up. Verified live on 2026-09-13 with real recalls (Boon NURSH bottles, Cade finger lights, Hampton Bay fan, 2019 Outback campaigns); 32 pytest tests cover it on the mock provider, including snoozes and late approvals (an approval releases the gate at once; a later one forks the run from the gate).
2. The web app (`web/`, Vite + React) implements the whole design handoff: the six dashboard pages with the shell, panels, dark/RTL/mobile, and `/flow/trace`, the full gren trace view (runs, canvas, drawer, inspector, gate approval) live over SSE; `npm run build` and `guardian serve` host it at http://127.0.0.1:8787, `VITE_MOCK=1 npm run dev` runs it with no backend.
3. AWS: the account (779457758734, us-east-1) is set up per `docs/AWS_SETUP.md` (AWS CLI profile `guardian` via `aws login`, Agent Toolkit, Bedrock model ids confirmed) but was still `PENDING_ACTIVATION` on the AWS side when this was written, so no live Bedrock call has succeeded yet. The AgentCore deployment is built and tested locally (`deploy/agentcore`, `python scripts/package_agent.py`, `agentcore dev`; deployed mode in the API via `GUARDIAN_AGENT_RUNTIME_ARN` + `GUARDIAN_S3_BUCKET`) and waits on: account active → Bedrock model access form → `agentcore deploy -y`. Still not built: SES/SNS delivery beyond the outbox, the demo video, `docs/architecture.png`, and the plan's Expanded tier (mailroom photos, grocery advisories, settlements).
