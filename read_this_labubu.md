# read_this_labubu.md

**Where things are (four lines):**

1. Guardian runs end to end on gren and Strands. Run `guardian seed`, then `guardian serve`. Click the logo (or run `guardian sweep`). The sweep pulls live CPSC, NHTSA, and openFDA recalls. It matches them in code. Opus adjudicates the ambiguous pairs. A verifier checks the plan. The run stops at the household gate. After "Request full refund" in the dashboard, the agent writes and "sends" the remedy (to `var/household/outbox` until SES or SNS is configured). Then it schedules the follow-up. This was verified live on 2026-09-13 with real recalls (Boon NURSH bottles, Cade finger lights, Hampton Bay fan, 2019 Outback campaigns). 50 pytest tests cover it on the mock provider, including snoozes and late approvals. An approval releases the gate at once. A later approval forks the run from the gate.
2. The web app (`web/`, Vite and React) implements the full design handoff: the six dashboard pages with the shell, the panels, and dark, RTL, and mobile modes. The Agent flow tab is the full gren trace workbench. It has runs with filters and the graph canvas with run banners. Its drawer has an Overview with the narrative of Guardian, a Timeline, filterable Events, Metrics, Tasks with gate approval, Spec, and Output. Its inspector shows fan-out detail and can fork a run. Blueprints show graphs that have not run yet, with "Run this graph". The data is live over SSE. `/flow/trace` is the same workbench in full screen. `docs/AGENT_FLOW.md` is the audit behind it. It also explains how each run shape reads. `npm run build` and `guardian serve` host the app at http://127.0.0.1:8787. `VITE_MOCK=1 npm run dev` runs it with no backend.
